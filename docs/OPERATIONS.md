# 批次操作

1. 用带异常样例做阶段预览，查看列数、必填值和冲突记录。
2. 执行批次后，在业务阶段定位异常分组并核对原始记录键。
3. 修复来源文件，重新上传并执行。历史批次保留供复核。
4. 对账无差异且无坏行时可签发。对仍有差异的版本可填写暂缓意见。
5. 导出复核证据并保存于交接记录。

单文件 256 KiB，最多 2000 条逻辑记录。容器重启后保留批次。恢复时使用原 Docker Compose 数据卷。

## 客户历史维护

1. 上传事件 CSV 到 `POST /api/history/preview`，先看受影响区间、前后归属和待核原因，预览不写库。
2. 用 `POST /api/history/batches` 登记批次；同字节重放返回原批次且不新增事件。
3. 存在 `SETTLED_LOCKED`、`REVOKE_TARGET_MISSING` 等未处理冲突时发布被拒（409）。逐条在 `resolutions` 接口填写处理原因（确认冲突或来源更正），处理只追加留痕、不删账本事件。
4. 冲突清零后 `publish` 生成正式版本并把结算账期固化为账期锁；发布在单事务内完成，失败自动回滚，旧版本与证据保持可用。
5. 后续批次的晚到变更只能落在生效点至下一条确认变更之间，已锁账期的原归属始终保留。撤销只回退其指向的变更。
6. 通过批次 `evidence` 接口导出 JSON 依据并随交接存档。
